# qa-start：開單與產出討論文件

> **回覆使用者時**：一律依照 `CLAUDE.md` 的「怎麼跟使用者說話」，用教學、引導的方式回覆。使用者可能完全不懂程式：說清楚現在在第幾步、剛剛做了什麼、他現在要做什麼（點哪裡、打什麼字）、接下來會發生什麼。不要對使用者提技能名稱或程式檔名。

遵守專案根目錄 `CLAUDE.md` 的所有規則。這個技能做到「確認點一、二」就停，等使用者回饋。

## 1. 讀單

1. 從使用者訊息取出單號，例如 `ALL-14490`。
2. 用 Atlassian 連線的 `getJiraIssue` 讀取，`cloudId` 用 `inta.atlassian.net`。`fields` 要包含：`summary`、`description`、`status`、`issuetype`、`priority`、`parent`、`subtasks`、`issuelinks`、`comment`、`attachment`、`fixVersions`。`responseContentFormat` 用 `markdown`。
3. 子任務只看標題和狀態，判斷哪些部分已經上 UAT。
4. 附件無法下載時，記在待確認問題，請使用者貼關鍵內容。

## 2. 判斷專案

- 對照 `CLAUDE.md` 的專案對照表。跨後台與前台的單，放在負責設定的後台資料夾。
- PlatformWeb 目前暫停測試。前台相關的案例照常列出，但「要不要測」預設「不要」，並在重點說明原因。
- 判斷不出來就先問使用者，不要猜。

## 3. 探查畫面（需要時）

- 單子提到的後台功能已經在 UAT 時，登入看實際的入口、欄位、字數上限、選項。只看不改，不按儲存。
- 先查 `scripts/library/INDEX.md`，用現成動作走到要看的頁面（`node scripts/run-action.mjs ...`）。需要更多畫面資訊時，照 `qa-script` 技能第 3 步寫臨時探查腳本。帳密不能出現在指令或輸出裡，所以需要登入的頁面不要用 MCP 瀏覽器。
- 探查時發現值得重複使用的操作，記下來，之後用 `qa-script` 做成腳本。
- 探查截圖存到 `<單號資料夾>/screenshots/recon/`。

## 4. 建立單號資料夾

路徑：`<專案資料夾>/tickets/<單號>/`。

- `ticket.md`：照 `_templates/ticket.md`。開頭三行固定是：
  ```
  - 狀態：討論中
  - 連結：https://inta.atlassian.net/browse/<單號>
  - 討論文件：<Claude 文件連結>
  ```
  內容包含需求摘要、後台實際畫面、任務或規則表、核心邏輯、指定文案（一字不差照抄原文）、驗收條件、子任務狀態、已知缺陷。
- `test-cases.md` 先不寫，定案後才由 `qa-review` 產生。

## 5. 建立 Claude 線上文件

照 Claude Docs 的伺服器說明建立文件（先開骨架、打開給使用者看、再一段一段填）。標題：`<單號> <中文短名> 測試規劃`。結構固定四段：

1. **重點**：一段話說明這張單要做什麼。條列五到六個重點。附上「部分、專案、開發進度」表格。最後一句說明現在能測哪些。
2. **風險與待確認**：先寫最大的風險。接著用勾選清單列出待確認問題，每項粗體標題加一句問題。開頭提示「每一項可以直接在後面打字回答，答完就勾起來」。
3. **核心測試案例**：15 到 25 條。
   - 先建立兩個下拉選單：「測試方式」，選項為 AI 測試、人工測試；「要不要測」，選項為要測、不要、再討論。
   - 表格欄位：編號、案例、預期結果、測試方式、要不要測、你的意見。
   - 「案例」寫一句話的操作，「預期結果」寫一句話的結果。
   - 測試方式依 `CLAUDE.md` 的 AI 與人工分工預先建議。「你的意見」留空。
   - 表格上方說明統計數字和填寫方式，表格下方說明哪幾條現在就能測。
4. **可補測的項目**：勾選清單，不在核心案例裡的測試點。最後一句指向 `ticket.md`。

## 6. 回報

在對話裡用三到五句說明重點，附上文件連結，請使用者在文件裡選、勾、寫意見，看完後說「看完了」。

把 `ticket.md` 的狀態維持為「討論中」。
