# qa-report：存證與測試報告

> **回覆使用者時**：一律依照 `CLAUDE.md` 的「怎麼跟使用者說話」，用教學、引導的方式回覆。使用者可能完全不懂程式：說清楚現在在第幾步、剛剛做了什麼、他現在要做什麼（點哪裡、打什麼字）、接下來會發生什麼。不要對使用者提技能名稱或程式檔名。

## 1. 收集結果

1. 讀 `ticket.md` 取得測試執行編號。
2. 用 `get_tests` 取得測試執行中每條案例的最新狀態，必要時用 `get_results` 看說明與缺陷編號。TestRail 是狀態的主檔，本機的結果檔只當截圖索引。
   - 決定紀錄寫了「不使用 TestRail」時，AI 案例用本機 `results/` 的結果；人工案例請使用者在對話裡告訴你結果，記進 `test-cases.md`。報告的「證據」段落改寫成本機路徑。
3. 還有「未測」的案例時，先列給使用者，問要等還是直接出報告。

## 2. 報告內容

用 Claude Docs 建立文件，標題：`<單號> <中文短名> 測試報告`。結構：

1. **結論**：一句話，例如「22 條通過 20 條，2 條失敗，建議修正後再上線」。
2. **總覽**：通過、失敗、阻擋、未測的數量，AI 和人工分開列。
3. **逐條結果**：編號、標題、測試方式、結果、說明。
4. **缺陷**：每個失敗的案例寫重現步驟、預期結果、實際結果，附上缺陷單號（有建立的話）。
5. **本次不測**：列出不測的案例與原因，以及這帶來的風險。
6. **證據**：TestRail 測試執行連結，以及截圖在 git 裡的路徑。

失敗案例的截圖要上傳到文件裡，放在該缺陷段落。

同一份內容另外存成 `<單號資料夾>/report.md`，照 `_templates/report.md` 的格式。

## 3. 確認點四

報告給使用者看過、同意後才進行下一步。不要自動在 Jira 留言。使用者要求時，才把報告連結留言到 Jira 單子。

## 4. 提交到 git

1. 確認 `.env`、`node_modules/`、`.auth/` 都在 `.gitignore` 裡，`git status` 不能出現這些。
2. 只加入這張單的資料夾：`git add <單號資料夾>`。
3. 提交訊息：
   ```
   QA <單號>：<中文短名> 測試完成

   結果：通過 N、失敗 N、阻擋 N
   TestRail：R<編號>
   ```
   結尾加上系統要求的共同作者行。
4. 不要推送到遠端，除非使用者要求。

## 5. 收尾

`ticket.md` 狀態改為「已完成」，並加上報告連結：`- 測試報告：<連結>`。
