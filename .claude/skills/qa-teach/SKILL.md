# qa-teach：看使用者示範，學會一個新動作

> **回覆使用者時**：一律依照 `CLAUDE.md` 的「怎麼跟使用者說話」，用教學、引導的方式回覆。使用者可能完全不懂程式：說清楚現在在第幾步、剛剛做了什麼、他現在要做什麼（點哪裡、打什麼字）、接下來會發生什麼。不要對使用者提技能名稱或程式檔名。

這個技能負責「錄製與理解」，把錄到的東西做成腳本的部分，照 `qa-script` 技能的寫法規則（第 5 到第 7 步）做。

教學流程共四步，回覆時用「教學第 N 步（共 4 步）」讓使用者知道在哪裡：

1. 講好要教什麼
2. 你示範一次（錄製）
3. 我說給你聽我學到什麼，你確認
4. 我自己做一次給你看，存進腳本庫

## 教學第 1 步：講好要教什麼

先查 `scripts/library/INDEX.md`。已經會的就直接說「這個我已經會了」，並示範一次，不用重教。

還不會的，一次問一件事，問清楚：

1. **教什麼**：例如「註冊新帳號」「過初級 KYC」。
2. **在哪個網站**：前台哪個版型（預設 m8），或哪個後台。
3. **要不要先登入**：教登入、註冊時不用；教 KYC、存款這類登入後的流程時要，我會先幫你登入好，你直接從登入後開始操作。
4. **會不會留下資料**：例如註冊會建立帳號、KYC 會送出資料。提醒使用者：測試資料名稱請用 `QA-TEST-` 開頭（例如 Email 寫 `qa-test-1106@…`），而且只在 UAT 操作。
5. **需要什麼測試資料**：例如測試用的手機號碼、證件圖片。沒有的話先請使用者準備。

## 教學第 2 步：示範（錄製）

1. 先跟使用者說明接下來會發生什麼：
   - 等一下會跳出一個新的瀏覽器視窗，旁邊有一個小工具列，那是錄製工具，不用理它。
   - 照平常的方式操作一次就好，不用刻意放慢。
   - 做完之後，**把那個瀏覽器視窗關掉**，錄製就會結束，我會自動收到。
   - 要輸入密碼時，照常輸入即可。錄到的帳密會自動換成代號，不會留下明碼，也不會給 AI 看到。
2. 在背景執行錄製（用 Bash 的背景執行，不要等它），指令依情況選擇：
   ```
   node scripts/record.mjs --project platform-web --variant m8 --name <教什麼>
   node scripts/record.mjs --project platform-web --variant m8 --login --name <教什麼>
   node scripts/record.mjs --project platform-admin --login --name <教什麼>
   ```
   要用手機尺寸錄就加 `--mobile`。
3. 告訴使用者「視窗應該已經跳出來了，請開始操作，做完關掉視窗」，然後停下來等，不要做別的事。
4. 收到錄製結束的通知後，看輸出訊息：
   - 「沒有錄到任何操作」：可能視窗太早關掉，問使用者要不要再錄一次。
   - 有錄到：進入第 3 步。

## 教學第 3 步：說給使用者聽，確認

1. 讀 `tmp/recordings/` 裡這次的兩個檔案：
   - `<時間>-<名稱>.mjs`：錄到的每一個操作。帳密已換成 `<變數名稱>`。前台與後台密碼可能相同，代號可能標成別的專案的變數，依情境換成正確的那個。
   - `<時間>-<名稱>-api.md`：錄製期間網頁呼叫的後端 API。用來找「畫面上的數字或結果是從哪裡來的」，之後驗證時可以直接比對後端回傳。
2. 用白話、編號列出「我看到你做了這些事」，每步一句，例如：
   > 1. 打開首頁，點右上角「Sign Up」
   > 2. 在 Email 欄位輸入一個測試信箱
   > 3. 按「Send code」，在 6 格裡輸入驗證碼
   > 4. ……
3. 一次問清楚三件事（可以合成一則訊息，但每件事分開列）：
   - 哪些值每次都會不同？例如 Email、手機號碼、證件號碼。這些會變成參數。
   - 做完之後，看到什麼代表成功？例如跳到某個頁面、出現某句話、KYC 等級變成 Basic。
   - 中間有沒有可能出現別的狀況？例如驗證碼視窗不一定出現、某些彈窗。
4. 錄到的步驟裡如果有明顯多餘的操作（點錯又點回來、捲動頁面），整理時直接拿掉，跟使用者說一聲就好。

## 教學第 4 步：自己做一次，存進腳本庫

1. 依照 `qa-script` 技能第 5 步的寫法規則，把錄到的操作改寫成腳本庫的動作：
   - 錄製工具產生的定位方式通常可以沿用，但要補上中英文兩種文字。
   - 帳密的代號改成從 `.env` 讀取（用 `scripts/lib/qa.mjs` 的 `loadEnv` 或現成的 `login`）。
   - 每次不同的值改成參數；需要不重複的值（例如 Email），用 `testName()` 產生，並以 `QA-TEST` 開頭。
   - 第 3 步確認的「成功條件」寫成檢查，做不到就丟出中文錯誤訊息。
   - 能用現成動作的就直接呼叫（例如先 `platform-web/login`），不要重複寫。
   - 副作用寫進 `meta.sideEffects`，例如「會建立一個新的前台帳號，無法刪除」。
2. 跟使用者說「我現在自己做一次給你看」，用看得到的瀏覽器跑：
   ```
   node scripts/run-action.mjs --headed <動作編號> key=value
   ```
   跑完把最後一張截圖給使用者看，請他確認「是不是跟你做的一樣」。
3. 使用者說不對，就問哪裡不對，修改後再跑一次。
4. 使用者確認後：
   - 執行 `node scripts/library/build-index.mjs` 更新腳本庫索引。
   - 把這次學到的注意事項寫進該專案的 `project.md`「注意事項」。
   - 刪掉 `tmp/recordings/` 裡這次的錄製檔。
5. 用白話告訴使用者：學會了什麼、以後怎麼用（例如「之後測到需要新帳號的單，我會自動用這個動作註冊一個」），以及留下了哪些測試資料。

## 注意

- 錄製只能在 UAT 網址進行。使用者開到其他網址時，提醒他回到 UAT 再錄。
- 不要把錄製檔、登入狀態檔（`.auth/`）提交到 git；它們已經在 `.gitignore` 裡。
- 錄製工具需要能顯示視窗的電腦。遠端或沒有螢幕的環境不能用，這時改用 `qa-script` 的「用說的」方式教。
